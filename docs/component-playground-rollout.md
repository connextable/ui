# 컴포넌트 플레이그라운드 개편 계획

`UIButton`과 `UIIconButton` 문서를 출발점으로 삼는다. 사용자는 기본 프로퍼티로 완성된 컴포넌트를 사용하고, 플레이그라운드에서 값을 바꾸고, 그 상태를 재현하는 Vue SFC를 복사할 수 있다. 기본 속성과 상태는 사용법에서 설명하고, 실제 조합과 특수 동작은 별도 예제로 다룬다.

## 조사와 진행도

개편 전 사이드바의 93개 페이지를 브라우저에서 열었다. 92개에서 첫 Vue SFC가 기본으로 펼쳐져 있었고, 페이지네이션은 500을 반환했다. 카탈로그에서 등록한 상세 예제 425개와 파일 425개가 일치했다. 공통 카탈로그 82개 중 67개는 예제 분류를 자동 생성한다. 12개 예제 소스에 플레이그라운드 내부 import가 있다. 이 수치는 개편 전 기준이다. 아래 작업표에는 버튼 페이지에서 다루는 `UIIconButton`과 `UIToggleButton`을 별도 항목으로 넣었다.

| 순서 | 작업 | 상태 |
| --- | --- | --- |
| 1 | 페이지네이션 500 복구 | 완료 |
| 2 | 공통 예제 레이아웃, 코드 생성 및 분류 경로 | 완료 |
| 3 | 동작·폼 → 선택 → 날짜·시간 → 탐색·오버레이 → 레이아웃·상태 → 표·데이터·가상화 | 95개 확인 |
| 4 | 공개 API 및 전체 경로 대조, 프로덕션 검증 | 완료 |

기본 구성, 상세 예제와 공개 API를 대조하고 컴포넌트 묶음별 대표 동작을 재검증했다. 트리 그리드의 그룹 선택 예제까지 완료해 총 95개 항목을 확인했다. 공통 참조 문서와 링크 점검 결과는 [카탈로그 참조 문서 개편](./component-reference-rollout.md)에 기록한다.

### 검증 기록

- 82개 공통 가이드의 상세 예제 참조 428건과 원본 파일 425개를 대조했다. 각 참조는 해당 페이지의 한 섹션에 들어가며 세 예제는 재정렬 두 페이지에서 공유한다. 기본 설정과 상태를 위로 배치하고 외부 제어·연동과 사용자 정의를 별도 섹션으로 옮겼다.
- 선택 문서는 단일 루트와 모델 중심으로 바꿨다. 트리의 노드 이름, 계층 목록의 열과 경로, 색상 영역과 입력은 루트에서 기본으로 구성한다. 브라우저에서 체크 그룹의 출력, 라디오 가로 방향키와 초기화, 목록·콤보박스 선택, 별점 변경과 초기화, 두 목록 간 일괄 이동을 확인했다. 트리에서 혼합 → 전체 선택 → 미선택을 확인했고, 검색한 팀을 선택하면 커서가 표시 이름 끝으로 이동했다. 계층 목록에서 도쿄를 선택하고 지웠고, 계층 팝업에서 부산을 고르면 전체 경로가 표시됐다.
- 탭과 스테퍼에서 항목 데이터로 버튼과 패널을 구성한다. 기본 탭을 오른쪽 방향키로 활동으로 변경했고, 스테퍼의 다음 버튼으로 배송에서 결제로 이동했다. 트리 보기에서 대시보드 그룹을 접었다. 공통 날짜 기준일 예제에는 완성된 달력을 사용했고, 첫 화면의 2026년 8월과 기준일 22일을 확인했다.
- 날짜·시간 18종에서 기본 코드의 모델 연결과 화면 표시를 대조했다. 날짜 칸은 가로와 세로가 같았고 편집하는 범위 필드의 두 입력은 같은 줄에 놓였다. 일시 범위에서 종료 시간을 16:31로 바꾸고 시·분 선택 항목이 각 열의 가운데에 표시되는 것을 확인했다. 로케일·입력 서식, 명시한 분·초·밀리초와 범위 끝점의 SSR 테스트를 통과했다.
- 다이얼로그의 Escape 복귀 포커스, 드로어 조건 적용, 시트 선택과 닫기, 경고 취소, 팝오버 저장, 툴팁 키보드 진입과 닫기, 토스트 닫기를 확인했다. 메뉴 명령과 컨텍스트 메뉴의 파일 복제, 메뉴 버튼의 포커스 복귀도 확인했다.
- 아코디언 열기와 접기, 캐러셀 다음 항목과 표시점 선택, 타이머 실행·정지·초기화, 분할선 방향키, 로컬 표 페이지 전환과 데이터 축소, 그리드 셀 이동을 확인했다. 가상화 5종은 Page Down으로 이동했고 재정렬은 키보드 확정 및 취소를 확인했다.
- 프로덕션 미리보기 93개 경로에서 첫 예제 코드가 열린 상태로 표시됐다. 너비 480px에서는 대표 화면 13개의 문서에 가로 넘침이 없었다. 480px 라이트박스의 폭은 화면과 같았고, 썸네일을 숨긴 상태에서 이전·다음 버튼을 사용할 수 있었다. 데스크톱에서는 마지막 항목에서 첫 항목으로 이동하고 다른 사진을 다시 열었다.
- Editable의 첫 코드 패널은 페이지 진입과 새로고침 직후 모두 243.375px로 표시됐다. Enter로 접고 다시 펼칠 때는 중간 높이를 거쳐 전환했다. 기본 입력의 지우기 버튼은 프레임 위·아래·오른쪽에서 5px씩 떨어져 있었다.
- 패키지 빌드의 공개 이름 585개를 카탈로그와 대조했다. 컴포넌트 560개와 `useUI*` 19개를 포함해 누락이 없었다. 미디어 예제의 샘플 데이터와 Feed 예제의 상대 스타일을 복사 코드 안에 넣었다.
- 브라우저 확인은 Chromium 미리보기에서 실행했다. 실제 모바일 기기의 스와이프와 모든 상세 예제의 조작 조합은 별도 확인이 필요하다.
- 페이지네이션 초기 렌더링과 첫 코드 열린 상태를 확인했다. 브라우저에서 마지막 페이지와 첫 페이지로 이동했을 때 `7 / 7`과 `1 / 7`이 표시됐다. 페이지 크기를 20에서 40으로 바꾸면 마지막 페이지가 12에서 6으로 변경됐고, 인접 페이지 예제에서 6에서 7로 이동하면 7이 현재 페이지로 표시됐다.
- 공통 프레임에서 카탈로그 예제가 헤더와 푸터를 채울 수 있고, 정적·실시간 코드를 동일한 버튼으로 복사할 수 있다. 브라우저에서 두 종류의 클립보드 결과를 코드 영역과 대조했다.
- 툴바의 가로 서식 적용, 세로 방향키 이동, 비활성 도구 건너뛰기, 복제 결과를 확인했다. 첫 코드에서 공통 레이아웃과 푸터를 제외한 Vue SFC를 확인했다.
- 입력의 크기·모양·초기화·비활성 설정을 바꿨을 때 동작과 코드가 일치했다. 편집과 초기화 결과, 읽기 전용과 오류 상태, 폼 제출을 브라우저에서 확인했다.
- 인라인 편집에서 Enter 확정, Escape 취소, 포커스 이탈 확정, 읽기 전용, 짧은 초안의 검증과 재확정을 확인했다.
- 인증 코드에서 자리 수 변경, 마스킹, 붙여넣기, 완료, 초기화를 확인했다. 이미 채운 코드의 세 번째 칸을 선택해 `2846`을 `2896`으로 수정했다.
- 태그 입력에서 칩 표면 대비, 추가·삭제, 중복 제외 붙여넣기, 기본과 사용자 정의 전체 지우기를 확인했다. 브라우저의 합성 이벤트를 사용해 조합 중 Enter에서 값이 유지되고 조합이 끝난 후 한국어 태그가 한 번만 추가되는 것을 확인했다.
- 숫자 입력에서 소수 확정과 지우기, 상한 초과 시 이전 확정값 유지, 폼에서 단위 없는 숫자 제출을 확인했다.
- 증감 버튼은 배치와 증분 변경, 방향키, Page Up, 최솟값을 확인했다. 수량 필드는 `1.25 m`를 `125 cm`로 표시하고, `150 cm`를 입력하면 모델에 `1.5 m`가 확정되는 것을 확인했다.
- 슬라이더의 방향 변경, 증분, 읽기 전용, 값 읽기 서식을 확인했다. 범위 슬라이더에서 손잡이 사이 채움과 최소 간격을 확인했고 세로 슬라이더가 `500–500`으로 겹친 상태에서 실제로 끌어 범위를 다시 넓혔다.
- 파일 입력에서 파일 선택·삭제, 이미지 붙여넣기, 파일 개수와 전체 용량 제한을 확인했다. 브라우저의 드롭 이벤트로 전달한 파일이 모델에 반영되는 것을 확인했다.
- 파일 업로드는 기본 브라우저 선택과 교체, 전송 취소, 실패 후 재시도, 세 항목 대기열 완료를 확인했다. 상세 예제에서 각 어댑터를 직접 import 없이 실행할 수 있게 정리했다.
- 폼 제출 및 초기화, 스키마로 숫자 변환, 동적 필드 추가·삭제, 저장 오류 후 재시도, 포커스 이탈 검증 및 입력 중 오류 해제, 방문과 변경 상태 구독을 확인했다.
- 버튼 문서에서 로딩 전후 너비, `block` 배치, Nuxt 링크 주소와 폼 연결을 확인했다. 아이콘 버튼에서 원형 크기와 기본·사용자 지정 스피너를, 토글 버튼에서 `aria-pressed` 변화를 확인했다.
- 작업표의 이름을 사이드바 목록과 대조해 누락과 중복이 없는 것을 확인했다. 이번 변경분으로 만든 프로덕션 빌드에서 93개 경로가 첫 코드까지 렌더링됐다. 브라우저 너비 480px에서 수정한 13개 페이지는 바깥 가로 스크롤이 생기지 않았다.

## 공통 완료 조건

- 기본 예제는 가능한 한 단일 루트에 props와 `v-model`을 사용한다. 여러 컴포넌트가 실제로 협력하는 예제에는 해당 조합을 보여 준다. 기존 슬롯으로 직접 조립하거나 스타일을 바꾸는 경로를 유지한다.
- 공통 예제 프레임은 조작할 설정이 있을 때 헤더, 표시할 결과가 있을 때 푸터를 렌더링한다. 두 경계선은 전체 너비를 차지한다. 코드 접기 버튼은 푸터 뒤에 배치한다. 첫 코드는 페이지 진입 즉시 최종 높이로 표시하고, 사용자가 접거나 펼칠 때 높이를 전환한다.
- 코드는 필요한 import와 데이터가 들어 있는 `<script setup lang="ts">`, `<template>`, 필요한 경우 `<style scoped>`로 구성한다. Vue 포매터를 적용한다. 상태를 편집하는 예제는 `v-model`을 사용하고 true인 Vue boolean props는 축약한다. 실시간 조작값과 예제 코드의 props가 일치한다.
- 기존 링크, 목차 앵커, 키보드 동작과 좁은 화면 레이아웃을 유지한다. 컴포넌트 묶음마다 대표 예제의 조작과 복사를 브라우저에서 확인하고 단위별로 커밋한다.
- 마지막에 전체 93개 페이지의 정상 렌더링과 첫 코드 열림, 상세 예제의 등록과 파일 일치, 공개 내보내기의 문서 색인 포함 여부를 확인한다. 처음 조사에서 색인 밖에 있던 UI 컴포넌트 15개와 `useUI*` 19개도 확인한다. 각 항목은 관련 루트의 API 또는 독립 안내에서 찾을 수 있어야 한다.

## 색인에서 확인할 공개 API

- 선택·폼의 `UICheckboxTreeIndicator`, `UIClearButton`, `UIFieldClear`, `UIRadioGroupItem`, `UIRadioGroupIndicator`
- 폼 문서에 추가한 `UIFormDescription`, `UIFormLabel`, `UIFormMessage`
- 날짜·진행 상태의 `UIDatePickerValue`, `UIProgressIndicator`, `UIProgressTrack`, `UIProgressValueText`
- 표의 `UITabularColumnAction`, `UITabularColumnHeading`, `UITabularFilterPopover`

- [x] `UIIconButton` · 기본·사용자 지정 스피너, 원형과 입력 안 모양, 접근성 이름
- [x] `UIToggleButton` · 눌림 상태, 앞뒤 아이콘, 폼 안 동작
- [x] `UIToolbar` · 가로·세로, 구분선, 비활성, 방향키 이동
- [x] `UIInput` · 모델, 아이콘과 초기화, 오류, 읽기 전용, 폼 제출
- [x] `UIEditable` · 편집과 확정, Escape·blur, 검증
- [x] `UIPinInput` · 길이, 마스킹, 붙여넣기, 완료와 수정
- [x] `UITagsInput` · 칩 표면 대비, 추가·삭제·초기화, 붙여넣기와 중복·IME

- [x] `UISpinButton` · 증분, 큰 단위 이동, 범위, 키보드

- [x] `UISlider` · 방향, 증분, 읽기 전용, 키보드, 값 표시
