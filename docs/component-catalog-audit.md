# 컴포넌트 카탈로그 점검

2026-11-21에 로컬 Playground 사이드바가 제공한 컴포넌트 페이지 90개와 예제 560개를 확인했다. 브라우저에서 기본 화면의 제목, 예제 영역, 페이지와 예제의 가로 넘침, 노출된 기본 셀렉트와 이름 없는 아이콘 버튼을 조사했다. 기본 화면은 CSS 뷰포트 1910px와 582px에서, 좁은 화면은 391px에서 관찰했다.

차트와 가상화의 지연 예제 73개는 각 예제 앵커로 이동한 뒤 실제 콘텐츠가 들어오는지 확인했다. 아래 ‘조작 확인’은 문제를 재현하고 해당 동작을 다시 확인한 화면을 뜻한다. 기본 레이아웃 점검은 모든 브라우저와 모든 상태 조합의 조작을 포함하지 않는다.

## 발견한 문제와 재검증

| 영역 | 재현 근거 | 변경과 재검증 |
| --- | --- | --- |
| 데이터 그리드 상태 필터 | `data-grid-filter` 팝오버 안에서 네이티브 목록이 열렸다. | `UISelect` 선택을 Sectile `set-query`에 연결했다. ‘대기’를 선택하면 1행, ‘전체 상태’로 돌아가면 2행이 표시됐다. |
| 수량 입력의 단위 | 전체 순회 중 `quantity-field-unit`에서 기본 셀렉트가 실제로 노출됐다. 폼과 날짜·시간에서 발견된 다른 셀렉트는 기본 화면에서 숨겨져 있었다. | `UISelect`를 기존 `display-unit`에 연결했다. 1.25m에서 cm를 고르면 입력값은 125로 바뀌었다. |
| 아코디언 | 기본 예제의 헤더에 펼침 표시가 없고, 패널에 영문 식별자가 그대로 보였다. | `UIButton`과 Lucide Chevron, Disclosure와 같은 펼침 스타일을 적용했다. 열기·교체·접기와 비활성 항목을 확인했다. |
| Disclosure | 펼친 내용이 버튼에 붙었고, 구분선이 있는 예제에서도 본문 여백이 부족했다. | 버튼과 본문의 좌우 기준을 맞췄다. Space로 열었을 때 220ms 높이 전환이 동작했고, 코드 보기에서 소스가 기존 프레임 안에 표시됐다. |
| 페이지네이션 | 이동 레이블이 길어 2줄로 나뉘었다. 391px에서는 한 줄을 유지하더라도 끝의 이동 버튼이 처음에 보이지 않았다. | Lucide 아이콘과 현재 페이지로 한 줄을 구성했다. 좁은 컨테이너에선 이전·다음과 현재 페이지를 남긴다. 391px에서 1→2→1과 페이지 크기 20→40을 확인했다. |
| 캐러셀 | 인디케이터에 슬라이드 식별자 텍스트가 들어가 타원으로 늘어났고, 수동 예제에도 일시 정지 버튼이 있었다. | 점 버튼의 클릭 영역을 36px로 맞췄고 현재 점을 색으로 표시한다. 이전·다음, 인디케이터 직접 이동, 자동 재생 일시 정지와 재개를 확인했다. |
| 좁은 화면의 공통 미리보기 | 391px에서 21개 페이지에 가로 넘침이 있었다. 폼 예제의 내부 폭이 할당 폭보다 최대 86px 컸다. | 미리보기 그리드와 폼 예제의 최소 너비를 제한했다. 아래 표의 대상들을 재검사해 문서 가로 넘침이 사라진 것을 확인했다. |
| 분할 패널 | 좁은 패널의 긴 코드 줄이 문서까지 밀었다. Handle에 넣은 접근성 이름도 기본 영문 이름으로 바뀌었다. | 코드 줄은 패널 안에서 스크롤하고 라벨은 Root에 연결했다. 391px에서 문서 폭 391px, 코드 영역 181px, 코드 내용 282px를 관찰했다. 오른쪽 방향키로 분할 값이 34→35로 변경됐다. |
| 트리 그리드 그룹 선택 | 그룹 컨트롤은 `request-bulk-selection`을 전달했지만 예제가 명령을 처리하지 않았다. | 로컬 소스의 하위 행 두 개를 선택하도록 명령을 연결했다. 클릭 후 웹사이트와 API 행이 모두 선택됐다. |

### 오버레이 모션·탭·선택 목록 후속 확인

- 트리거 위치에 따른 시작점, 화면 가장자리에서의 방향 전환, 진입·퇴장 타이밍을 조사했다. Sectile이 확정한 방향을 기준으로 패널이 트리거 쪽에서 나타나고, 닫힐 때는 더 짧게 이동하며 사라진다. [Animations.dev](https://animations.dev/vocabulary), [Emil Kowalski의 예제](https://emilkowal.ski/ui/7-practical-animation-tips), [Radix Popover](https://www.radix-ui.com/primitives/docs/components/popover), [Carbon 모션 가이드](https://carbondesignsystem.com/guidelines/motion/overview/)
- 브라우저에서 Popover의 진입 220ms·퇴장 140ms, 닫히는 중 재열기, 오른쪽 Tooltip의 가로 진입과 페이드 퇴장을 재현했다. Select는 열고 닫을 때 트리거 폭이 약 123px로 같았고, MenuButton과 날짜 선택 창에도 진입 전환이 적용됐다.
- Combobox의 Production·Stage·Development와 Select·MenuButton의 인접 항목에서 2px 간격을 측정했다. 수동 탭은 391px에서 방향키로 포커스만 이동했고 Enter를 누르면 선택 배경과 본문이 바뀌었다. 전환 중 탭 위치와 문서 너비는 유지됐다.

### Sectile에 전달할 재현 근거

`/components/data-tree-grid#data-tree-grid-group-selection`에서 ‘하위 서비스 모두 선택’을 누르면 하위 행 두 개는 체크되지만, 그룹 컨트롤의 `aria-checked`는 `false`로 남는다. 전체 카탈로그 재점검에서도 이 동작을 재현했다. 현재 설치된 Sectile 그리드 연결은 `group-leaves` 대상의 그룹 체크 상태를 항상 `unchecked`로 설정한다. 소스가 확정한 그룹의 선택 범위로부터 `unchecked`, `mixed`, `checked`를 전달할 수 있는 계약이 필요하다.

### 전체 카탈로그 재점검

사이드바에 등록된 90개 경로와 예제 영역 560개를 다시 확인했다. CSS 뷰포트 1302px와 326px에서 페이지 제목, 예제 영역, 문서·예제의 가로 넘침을 측정했다. 각 페이지의 기본 예제에서 코드를 열었고 차트·가상화의 지연 예제 73개는 직접 스크롤해 콘텐츠가 표시되는 것을 확인했다. 아래 조작 기록은 변경 사항을 재현하고 수정 후 다시 실행한 사례다.

| 영역 | 확인한 문제 | 수정 후 브라우저 결과 |
| --- | --- | --- |
| SpinButton | 증감 버튼과 입력의 높이가 달랐고 숫자 입력이 넓게 늘어났다. stamp.is-web은 주문 수량에 좌우 증감, 제작 치수에 단위와 세로 증감을 쓴다. | 공통 테두리로 묶은 수량형과 치수형을 만들었다. 주문 수량은 4→5, 제작 가로 길이는 28.5→29mm로 바뀌었다. |
| QuantityField | 단위가 입력과 분리되고 값 슬롯이 비어 있었다. | 한 입력 그룹에 고정 단위 또는 UISelect를 붙였다. 포장 길이 1.25m→125cm와 배송 무게 0.65kg→650g을 확인했다. 기준값 표시는 각각 1.25m, 0.65kg였다. 길이 입력을 2.5로 확정하면 결과도 2.5m가 된다. |
| NumberField | 기본 NumberField가 다른 텍스트 입력과 별도의 스타일을 썼다. | 공통 입력 스타일을 적용했다. 12.75 확정, 범위 밖 할인율 110 입력 시 마지막 확정값 50 유지, 폼에서 수량 32 제출을 확인했다. |
| Calendar·RangeCalendar·TemporalProvider | 326px에서 그리드가 달력의 320px 고유 너비를 유지해 문서 오른쪽으로 26px 넘쳤다. | 폼과 기준 날짜 예제의 그리드 열이 축소되도록 했다. 세 화면에서 문서 너비와 스크롤 너비가 모두 326px였다. |
| 날짜·시간 개발 미리보기 | Vite가 날짜·시간 포맷 진입점을 별도로 최적화한 상태에서, 포맷 등록 확인이 실패해 페이지가 500으로 바뀌었다. | Sectile의 temporal 진입점이 하나의 포맷 등록부를 공유하도록 설정했다. 일시 범위의 초 단위 예제에서 09:00:00과 18:00:00이 표시됐고 코드 펼침도 동작했다. |

### 인터랙션 스타일 비교

Playground 사이드바의 90개 경로를 프로덕션 빌드에서 열어, 기본 예제 바로 아래에 상태 비교가 한 번씩 표시되는지 확인했다. CSS 뷰포트 1910px에서 78개 페이지는 기본·호버·누르는 중·키보드 포커스, 데이터 테이블은 기본·행 호버, 가상화 예제 5개는 기본·스크롤 영역 포커스를 표시했다. 비교할 인터랙션 스타일이 없는 기본 예제 6개는 기본 샘플을 표시했다.

- UIButton의 배경은 기본 `rgb(36, 91, 115)`, 호버 `rgb(25, 70, 92)`, 누르는 중 `rgb(16, 51, 70)`이었다. 포커스 샘플에는 링이 표시됐고, 기본 예제의 버튼을 누르면 실행 횟수가 0에서 1로 바뀌었다.
- UINumberField의 `cm` 단위는 네 상태에서 보였다. 키보드 포커스 샘플은 바깥 그룹에만 링이 표시됐다.
- UIDataTable의 첫 행 배경은 기본에서 `rgb(255, 255, 255)`, 호버에서 `rgb(237, 241, 243)`이었다.
- CSS 뷰포트 469px의 UIButton 페이지에서 카드가 2열로 배치됐고 문서의 스크롤 너비는 469px였다.

### 사이드바와 상태 카드 후속 점검

- UIInput의 활성 배경은 펼침 아이콘이 있는 UISelect보다 왼쪽에서 40px 들어가 있었다. 여백을 행의 내부로 옮긴 뒤 두 행의 왼쪽 위치와 너비, 라벨 시작점이 일치했다. UISelect의 펼치기와 접기도 확인했다.
- CSS 뷰포트 1910px에서 90개 기본 샘플을 순회해 비교 대상과 카드 크기를 확인했다. 391px에서는 날짜·시간, 표, 차트, 가상화, 슬라이더를 포함한 32개 페이지를 다시 검사했다. 두 검사에서 샘플 외곽이나 문서가 가로로 넘친 사례는 없었다.
- 슬라이더는 카드 폭에 맞고, 표·트리·가상화 샘플은 아래쪽이 잘리지 않는다. 차트는 캔버스 비율을 유지하고 오버레이도 같은 폭으로 맞춘다. 1910px 뷰포트에서 차트 상태 카드의 기본 샘플 가로 넘침은 358px에서 0px로 줄었다.
- 달력은 날짜 셀에 포커스를 두고, 피커는 표시값과 열기 버튼을 함께 보여준다. 기준 날짜 달력의 요일은 기본 예제와 상태 카드 모두 7열로 표시됐다. 진행률 카드에는 진행 바가 들어갔고, 파일 업로드 카드에는 파일명과 전송 버튼이 표시됐다. 기본 예제에서 전송을 눌러 완료 메시지까지 확인했다.

### 상태별 시각 차이 확인

- 90개 페이지의 상태 카드에서 표시된 요소의 색, 테두리, 윤곽선, 그림자 등을 비교했다. 수정 전에는 62개 페이지에 같은 모습의 카드가 있었다. 공통 조작 스타일과 카드의 비교 대상을 수정한 뒤 CSS 뷰포트 1910px와 391px에서 각각 90개 페이지를 확인했다. 비교한 속성이 같은 카드는 한 카드에 상태 이름을 함께 표시했다. UIInput의 ‘호버 · 누르는 중’이 그 예다.
- UISlider와 UIMultiThumbSlider의 손잡이는 호버에서 옅은 채움과 바깥 원, 누름에서 강조색 채움, 키보드 포커스에서 포커스 링을 표시한다. 단일 슬라이더의 기본 예제는 방향키로 40→41, 손잡이 드래그로 41→67이 됐다.
- 세로 예제의 트랙은 단일과 범위 슬라이더 모두 8×144px로 표시됐다. 단일 슬라이더는 위쪽 방향키와 드래그로 40→41→62가 됐다. 범위 슬라이더는 아래쪽 손잡이를 위로 조작했을 때 120→130이 됐고 위쪽 손잡이 값은 340이었다.

### 표와 가상화의 키보드 포커스

- `UIDataTable` 기본 예제는 정적 HTML 표이며 셀이 Tab 순서에 들어가지 않는다. 고정 헤더 예제에서는 표 바깥 스크롤 영역에 포커스를 두고 PageDown으로 이동했다. `UIGrid` 기본 예제에서는 방향키로 월요일 09:00에서 10:30 셀로 이동했다.
- 가상 목록·그리드·메이슨리·공간 배치·가상 배치의 기본 예제는 이름이 있는 스크롤 영역을 한 번씩 Tab 순서에 넣는다. 다섯 곳에서 키보드 진입, PageDown 스크롤, Tab 이탈을 확인했다. 포커스 링은 항목 위에 겹치던 안쪽 위치에서 스크롤 영역 바깥으로 옮겼다. 기본 예제 아래에는 키보드 스크롤 안내가 표시된다.
- `UIDataGrid`의 작업 상태 기본 예제는 셀이 표시된 뒤에도 코드 보기에서 역탭했을 때 그리드로 진입하지 않았다.

### 재정렬과 날짜·시간 피커 후속 점검

- 재정렬의 ‘시스템 블록’은 놓는 위치만 검사해 드래그 미리보기가 나타났다. 항목을 이동 시작 단계에서 비활성화한 뒤 마우스 드래그와 Space로 들어 올리기가 시작되지 않는 것을 확인했다. 잠기지 않은 항목은 드래그 미리보기가 나타났고 키보드로도 순서를 바꿀 수 있었다. 전체 잠금 버튼과 목록 사이 간격은 12px이다.
- 즐겨찾기는 36×36px 별 버튼으로 표시한다. 전환 전후와 재정렬 미리보기에서 목록 높이는 194px, 행 높이는 53px이었다. 별 버튼에서 드래그해도 들어 올리기가 시작되지 않았다.
- 트리는 하위 항목에 단계당 24px 들여쓰기와 연결선을 표시한다. 상태 카드 안의 트리는 데스크톱에서 467px, 391px 뷰포트에서 326px 너비를 썼다. 두 화면에서 ‘컴포넌트’가 한 줄로 표시됐고 좁은 화면의 문서 너비는 391px이었다.
- 날짜·시간 피커 9종에서 값 영역의 배경이 투명하고 오른쪽 버튼이 36×36px인 것을 확인했다. 연도 범위의 `2030` 왼쪽에 보이던 그림자는 제거됐다.
- 날짜 피커의 연·월 제목을 누르면 연도 목록을 먼저 연다. 연도를 고르면 월 목록, 월을 고르면 일 달력으로 이동한다. 피커 내부의 연도 목록에서 별도의 팝업 진입 효과를 제거하고, 세 화면이 같은 높이의 영역을 번갈아 쓰도록 했다.
- 브라우저에서 날짜·날짜 범위·날짜 시간·날짜 시간 범위 피커의 높이는 287px, 월·월 범위 피커의 높이는 255px이었다. 16개 전환에서 416개 표본을 확인했고 각 표본에서 목록이 하나씩 표시됐다. 391px 화면에서도 날짜 범위 피커의 연도 목록을 닫았다가 다시 열거나 현재 연도를 선택했을 때 높이가 유지됐다. 키보드로 연도·월·일 셀에 이어서 포커스가 이동했고 `2027-09-16`부터 `2027-09-19`까지 선택한 값이 입력 영역에 들어갔다.

### 피커 아이콘과 범위 값 표시

- 날짜·월·연도·시간 피커 9종의 기본 예제에서 36×36px 버튼과 18×18px 아이콘을 확인했다. 한 줄 피커는 위·오른쪽·아래 간격이 약 5.7px로 같았고, 두 줄 일시 피커는 버튼을 첫 줄에 맞췄다.
- 날짜·월·연도 범위의 빈 값에 시작과 종료 안내가 표시됐다. 날짜 범위는 첫 날짜 선택 후에도 확정 전 상태를 표시했고 두 번째 날짜를 고르면 확정된 두 값이 나타났다. 391px 화면에서 날짜 범위 구분선과 두 날짜가 한 줄에 들어갔다. 표기 예제는 `2026. 08. 22.`와 `22 Aug 2026` 사이를 전환하며 같은 날짜를 유지했다. 달력으로 날짜를 다시 고르면 현재 표기 형식으로 갱신됐다.
