# 컴포넌트 카탈로그 점검

## 2026-11-23 요청 사항 재검토

이 대화에서 요청한 동작을 현재 카탈로그, 공개 API, 기존 테스트와 대조했다. 아래 기록은 최신 점검 결과다.

| 영역 | 확인한 계약과 결과 |
| --- | --- |
| 스크롤·시트·윈도우 분할 | `fade`는 기본으로 꺼져 있다. 예약표에서 고정 행·열 안쪽부터 적용되는 페이드 마스크를 확인했다. 시트 너비는 `size`, `block`과 CSS로 지정하고 스와이프를 켠 구성에서 손잡이를 표시한다. 분할선에는 기본 그립이 없으며 키보드와 실제 드래그로 크기를 바꿨다. 그립은 선택하거나 슬롯에서 꾸밀 수 있다. |
| 슬라이더 | 값 사이만 채우고 트랙과 손잡이에 공통 인셋을 쓴다. 세로 슬라이더에서 `500–500`에 겹친 이후 키보드와 포인터로 범위를 다시 넓혔다. 가격 예제에서는 손잡이 이름과 별도의 금액 출력을 사용한다. |
| 탐색과 문서 | 본문 배경은 흰색이다. 분류된 사이드바에서 컴포넌트 링크와 구성 항목 펼치기 버튼을 별도로 조작한다. 목차는 문서 끝에서 현재 제목까지 추적한다. 참조는 구성 요소의 역할과 API 종류, 여러 소속 컴포넌트를 제목으로 구분한다. |
| 라이트박스 | 영상은 기본 미디어 컨트롤을 사용하고, 사진 열기와 항목 이동에 View Transition을 연결한다. 데스크톱에서 반복 열기와 양방향 순환 중 한 다이얼로그가 유지됐다. 480px에서 패널 폭은 480px였고 썸네일은 숨겨졌다. 이전·다음 버튼은 작동했고 미디어 영역의 빈 공간은 투명했다. 터치 스와이프의 구현 경로를 확인했다. |
| 버튼과 링크 | 로딩이 끝나도 버튼의 가로·세로 치수가 같았다. 아이콘 전용 버튼에는 원형과 기본 스피너, 입력 안 액션에는 정사각형 인셋을 사용한다. `block`으로 가용 너비를 채운다. Nuxt 모듈에서 자동 import와 링크 컴포넌트를 선택할 수 있고, 지원하는 Nuxt 버전에서 앱의 프리패치 정책과 링크별 옵션을 적용한다. |
| 폼과 선택 | 읽기 전용·비활성화, 입력 안내, 폼 이름·필수 조건·제출·복귀 동작을 [공통 폼 계약](./form-control-contract.md)과 대조했다. PIN의 입력 완료를 확인했다. 수량 입력 X의 상·하·우 간격은 각각 5px였고, Select는 지운 뒤 오른쪽 화살표와 트리거 포커스를 유지했다. 트리 상세 예제는 공통 필드·펼침·선택 표시와 `v-model`을 사용한다. 다중 선택 이름과 커서 위치, 지우기 및 빈 검색 결과를 확인했다. |
| 날짜와 시간 | 날짜 셀은 정사각형이며 월·연도 범위의 시작점, 종료점과 선택 중 상태를 Sectile에서 읽는다. 동일 연도의 월 범위는 끝에서 연도를 한 번 줄여 표시한다. 달력은 연·월 탐색과 선택형 시간 모델을 제공한다. 일시 피커는 `input-layout`과 `portal`로 바꾼 구성에서도 공통 달력과 시간 열을 제공한다. 480px에서 시작·종료의 날짜와 시간이 한 줄에 놓였다. 분 단위 값은 `09:30`으로 표시됐고 저장된 초·밀리초는 유지한다. 시간 열의 선택값은 가운데에 놓였으며 수동 스크롤은 유지됐다. |
| 업로드와 트리 그리드 | 대기열은 공통 어댑터 빌더와 파일 목록으로 구성하고, 브라우저에서 `0 / 3 → 3 / 3 → 0 / 3`을 확인했다. 원격 트리 그리드는 `loadGroupLeafIDs`로 받은 멤버십을 바탕으로 일부 선택·전체 선택·해제를 처리했다. 접혀서 보이지 않는 하위 행도 상태에 포함됐다. |
| 예제와 초기 펼침 | 공통 프레임의 헤더, 미리보기, 선택적 푸터, 전체 너비 코드 버튼의 배치를 확인했다. 93개 경로의 서버 응답에서 첫 코드가 펼쳐져 있고 `script`와 `template`이 모두 있는지 검사하도록 확장했다. Vue 소스에서 `:prop="true"` 패턴을 전수 검색했다. 펼침 전환은 초기 렌더링 이후 공통 모션을 활성화한다. |
| Sectile | npm의 `@sectile/vue` 최신 안정 버전 `0.22.0`과 설치 버전이 일치했다. #239에 날짜 편집 서식, 월·연도 범위 끝점, 선택 중 범위 상태를 보충한 댓글이 게시된 것을 확인했다. 날짜·시간의 사용자 지정 편집 서식에서 Sectile 공개 API로 전달하기 어려운 항목은 호환 코드 한 곳에서 관리한다. [Sectile #239 댓글](https://github.com/sectile/sectile/issues/239#issuecomment-7075097369) |

워크스페이스 타입 검사와 패키지 테스트 34개, 플레이그라운드 프로덕션 빌드를 통과했다. 문서와 카탈로그 소스에서 공개 런타임 내보내기 594개의 이름을 대조했다. 93개 경로에서 최초 코드, 구성 참조 앵커 532개, 예제 링크 838개를 확인했다. 위 표의 대표 조작을 브라우저에서 수행했다. 실제 모바일 기기의 스와이프와 브라우저별 모션 프레임은 별도 검증 범위다.

## 기본 사용 API 전수 점검

공통 카탈로그 예제 82개와 전용 페이지 11개의 기본 예제를 공개 루트 및 구성 요소와 대조했다. 값과 설정으로 정해지는 구조, 앱이 제공해야 하는 콘텐츠, 예제에서만 추가한 출력이나 레이아웃을 확인했다. 이 항목은 기본 사용 API 소스 점검이며, 페이지별 모든 동작의 브라우저 점검은 별도다.

| 영역 | 확인한 결과 |
| --- | --- |
| 동작·입력 | `UIButton`, `UIInput`, `UINumberField`, `UITagsInput`, `UIFileInput`, `UISlider`, `UIMultiThumbSlider`에는 기본 구성이 있다. `UIEditable`, `UIPinInput`, `UISpinButton`, `UIQuantityField`는 내부 요소를 루트의 기본 구성으로 옮겼다. `UIToolbar`는 버튼과 액션을, `UIForm`은 스키마와 필드 배치를, `UIFileUpload`는 업로드 로직을 받는다. 파일 선택과 업로드를 묶는 공통 흐름은 추가 검토 대상으로 남았다. |
| 선택 | `UICheckbox`, `UIRadioGroup`, `UISwitch`, `UISelect`, `UITransfer`에는 기본 표시가 있다. `UICheckboxGroup`, `UIToggleGroup`, `UIListbox`는 옵션에서 항목을, `UICombobox`는 검색 데이터에서 입력과 결과를, `UIRating`은 값마다 별을 그리도록 바꿨다. `UITreeSelect`, `UICheckboxTree`, `UICascadeSelect`, `UICascadeList`는 노드의 레이블, 하위 항목 토글, 선택 경로 표시까지 공통 구성으로 옮길 수 있다. `UIColorPicker`에는 색 영역·손잡이·색상 조절·텍스트 입력을 함께 제공할 기본 구성이 필요하다. |
| 날짜·시간 | `UICalendar`, `UIRangeCalendar`, `UIDateField`, `UIDateRangeField`, `UIDatePicker`, `UIDateRangePicker`, `UIDateTimeField`, `UIDateTimeRangeField`, `UIDateTimePicker`, `UIDateTimeRangePicker`, `UITimeField`, `UITimePicker`, `UITimeRangeField`, `UIMonthPicker`, `UIMonthRangePicker`, `UIYearPicker`, `UIYearRangePicker`의 기본 예제는 루트로 동작한다. `UITemporalProvider` 기본 예제에 남은 달력 셀 조립은 기준일 설정을 설명하는 데 필요하지 않다. |
| 탐색 | `UIAnchor`, `UIPagination`에는 완성된 기본 구성이 있다. `UITabs`, `UIStepper`는 항목 구성과 패널 배치를 내부화하고 본문을 슬롯으로 받을 수 있다. `UITreeView`는 노드와 펼침 표시를 공통 구성으로 제공할 수 있다. `UINavigationMenu`, `UIMenu`, `UIMenuButton`, `UIContextMenu`, `UIMenubar`는 링크·명령·구분선 데이터에서 기본 목록을 그리고 사용자 정의 동작을 슬롯으로 받을 수 있다. |
| 오버레이 | `UILightbox`는 미디어 데이터로 탐색과 화면을 구성한다. `UIDialog`, `UIAlertDialog`, `UIDrawer`, `UISheet`, `UIPopover`는 앱에서 트리거와 본문을 지정하면서 포털·배경·제목·닫기 버튼을 라이브러리 기본 구성으로 제공할 수 있다. `UITooltip` 기본 예제는 트리거와 설명 외에 콘텐츠 및 화살표까지 배치한다. `UIToast` 예제는 제목, 닫기, 뷰포트를 직접 조립한다. |

| 표·데이터·가상화 | `UIDataTable`, `UIDataGrid`, `UIDataTreeGrid`는 열과 데이터에서 표를 구성하고 셀 표시를 바꿀 수 있다. `UIGrid`, `UITreeGrid`는 행·셀 구조를 조립한다. `UIChart`는 차트 타입과 축·계열을, `UISequenceReorder`, `UITreeReorder`는 이동할 항목과 그룹 구조를 표현한다. `UIVirtualList`, `UIVirtualGrid`, `UIVirtualMasonry`, `UIVirtualSpatial`은 데이터와 표시 슬롯을 받는다. `UIVirtualizer`는 범용 배치와 렌더링 제어를 제공하는 저수준 구성이다. |
| 기반 | `UIPrimitive`는 요소를 지정하고, `UIHostProvider`는 하위 컴포넌트에 포털 위치와 쓰기 방향을 전달한다. |

수량 필드의 `UIQuantityFieldValue`는 직접 조립한 기존 화면에서 확정값을 꺼내는 슬롯이다. 기본 예제는 루트의 `v-model`로 수치와 기준 단위를 받고, 표시 단위 선택이 필요한 경우 `display-units`를 전달한다. PIN 입력은 `length`로 자리 수를 지정한다. 나머지 컴포넌트의 기본 구성 후보는 위 표에 남겼다.

## 2026-11-21 브라우저 점검

로컬 Playground 사이드바가 제공한 컴포넌트 페이지 90개와 예제 560개를 확인했다. 브라우저에서 기본 화면의 제목, 예제 영역, 페이지와 예제의 가로 넘침, 노출된 기본 셀렉트와 이름 없는 아이콘 버튼을 조사했다. 기본 화면은 CSS 뷰포트 1910px와 582px에서, 좁은 화면은 391px에서 관찰했다.

차트와 가상화의 지연 예제 73개는 각 예제 앵커로 이동한 뒤 실제 콘텐츠가 들어오는지 확인했다. 아래 ‘조작 확인’은 문제를 재현하고 해당 동작을 다시 확인한 화면을 뜻한다. 기본 레이아웃 점검은 모든 브라우저와 모든 상태 조합의 조작을 포함하지 않는다.

## 발견한 문제와 재검증

| 영역 | 재현 근거 | 변경과 재검증 |
| --- | --- | --- |
| 데이터 그리드 상태 필터 | `data-grid-filter` 팝오버 안에서 네이티브 목록이 열렸다. | `UISelect` 선택을 Sectile `set-query`에 연결했다. ‘대기’를 선택하면 1행, ‘전체 상태’로 돌아가면 2행이 표시됐다. |
| 수량 입력의 단위 | 전체 순회 중 `quantity-field-unit`에서 기본 셀렉트가 실제로 노출됐다. 폼과 날짜·시간에서 발견된 다른 셀렉트는 기본 화면에서 숨겨져 있었다. | `UISelect`를 기존 `display-unit`에 연결했다. 1.25m에서 cm를 고르면 입력값은 125로 바뀌었다. |
| 아코디언 | 기본 예제의 헤더에 펼침 표시가 없고, 패널에 영문 식별자가 그대로 보였다. | `UIButton`과 Lucide Chevron, Disclosure와 같은 펼침 스타일을 적용했다. 열기·교체·접기와 비활성 항목을 확인했다. |
| Disclosure | 펼친 내용이 버튼에 붙었고, 구분선이 있는 예제에서도 본문 여백이 부족했다. | 버튼과 본문의 좌우 기준을 맞췄다. Space로 열었을 때 220ms 높이 전환이 동작했고, 코드 보기에서 소스가 기존 프레임 안에 표시됐다. |
| 페이지네이션 | 이동 레이블이 길어 2줄로 나뉘었다. 391px에서는 한 줄을 유지하더라도 끝의 이동 버튼이 처음에 보이지 않았다. | Lucide 아이콘과 현재 페이지로 한 줄을 구성했다. 좁은 컨테이너에선 이전·다음과 현재 페이지를 남긴다. 391px에서 1→2→1과 페이지 크기 20→40을 확인했다. |
| 캐러셀 | 인디케이터에 슬라이드 식별자 텍스트가 들어가 타원으로 늘어났고, 수동 예제에도 일시 정지 버튼이 있었다. | 점 버튼의 클릭 영역을 36px로 맞췄고 현재 점을 색으로 표시한다. 이전·다음, 인디케이터 직접 이동, 자동 재생 일시 정지와 재개를 확인했다. |
| 좁은 화면의 공통 미리보기 | 391px에서 21개 페이지에 가로 넘침이 있었다. 폼 예제의 내부 폭이 할당 폭보다 최대 86px 컸다. | 미리보기 그리드와 폼 예제의 최소 너비를 제한했다. 아래 표의 대상들을 재검사해 문서 가로 넘침이 사라진 것을 확인했다. |
| 분할 패널 | 좁은 패널의 긴 코드 줄이 문서까지 밀었다. Handle에 넣은 접근성 이름도 기본 영문 이름으로 바뀌었다. | 코드 줄은 패널 안에서 스크롤하고 라벨은 Root에 연결했다. 391px에서 문서 폭 391px, 코드 영역 181px, 코드 내용 282px를 관찰했다. 오른쪽 방향키로 분할 값이 34→35로 변경됐다. |
| 트리 그리드 그룹 선택 | 그룹 컨트롤은 `request-bulk-selection`을 전달했지만 예제가 명령을 처리하지 않았다. | 로컬 소스의 하위 행 두 개를 선택하도록 명령을 연결했다. 클릭 후 웹사이트와 API 행이 모두 선택됐다. |

### 오버레이 모션·탭·선택 목록 후속 확인

- 트리거 위치에 따른 시작점, 화면 가장자리에서의 방향 전환, 진입·퇴장 타이밍을 조사했다. Sectile이 확정한 방향을 기준으로 패널이 트리거 쪽에서 나타나고, 닫힐 때는 더 짧게 이동하며 사라진다. [Animations.dev](https://animations.dev/vocabulary), [Emil Kowalski의 예제](https://emilkowal.ski/ui/7-practical-animation-tips), [Radix Popover](https://www.radix-ui.com/primitives/docs/components/popover), [Carbon 모션 가이드](https://carbondesignsystem.com/guidelines/motion/overview/)

### 인터랙션 스타일 비교

Playground 사이드바의 90개 경로를 프로덕션 빌드에서 열어, 기본 예제 바로 아래에 상태 비교가 한 번씩 표시되는지 확인했다. CSS 뷰포트 1910px에서 78개 페이지는 기본·호버·누르는 중·키보드 포커스, 데이터 테이블은 기본·행 호버, 가상화 예제 5개는 기본·스크롤 영역 포커스를 표시했다. 비교할 인터랙션 스타일이 없는 기본 예제 6개는 기본 샘플을 표시했다.

- UIButton의 배경은 기본 `rgb(36, 91, 115)`, 호버 `rgb(25, 70, 92)`, 누르는 중 `rgb(16, 51, 70)`이었다. 포커스 샘플에는 링이 표시됐고, 기본 예제의 버튼을 누르면 실행 횟수가 0에서 1로 바뀌었다.
- UINumberField의 `cm` 단위는 네 상태에서 보였다. 키보드 포커스 샘플은 바깥 그룹에만 링이 표시됐다.
- UIDataTable의 첫 행 배경은 기본에서 `rgb(255, 255, 255)`, 호버에서 `rgb(237, 241, 243)`이었다.

### 사이드바와 상태 카드 후속 점검

- UIInput의 활성 배경은 펼침 아이콘이 있는 UISelect보다 왼쪽에서 40px 들어가 있었다. 여백을 행의 내부로 옮긴 뒤 두 행의 왼쪽 위치와 너비, 라벨 시작점이 일치했다. UISelect의 펼치기와 접기도 확인했다.

- `UIDataTable` 기본 예제는 정적 HTML 표이며 셀이 Tab 순서에 들어가지 않는다. 고정 헤더 예제에서는 표 바깥 스크롤 영역에 포커스를 두고 PageDown으로 이동했다. `UIGrid` 기본 예제에서는 방향키로 월요일 09:00에서 10:30 셀로 이동했다.

- `UIDataGrid`의 작업 상태 기본 예제는 셀이 표시된 뒤에도 코드 보기에서 역탭했을 때 그리드로 진입하지 않았다.

### 재정렬과 날짜·시간 피커 후속 점검

- 재정렬의 ‘시스템 블록’은 놓는 위치만 검사해 드래그 미리보기가 나타났다. 항목을 이동 시작 단계에서 비활성화한 뒤 마우스 드래그와 Space로 들어 올리기가 시작되지 않는 것을 확인했다. 잠기지 않은 항목은 드래그 미리보기가 나타났고 키보드로도 순서를 바꿀 수 있었다. 전체 잠금 버튼과 목록 사이 간격은 12px이다.
- 즐겨찾기는 36×36px 별 버튼으로 표시한다. 전환 전후와 재정렬 미리보기에서 목록 높이는 194px, 행 높이는 53px이었다. 별 버튼에서 드래그해도 들어 올리기가 시작되지 않았다.
- 트리는 하위 항목에 단계당 24px 들여쓰기와 연결선을 표시한다. 상태 카드 안의 트리는 데스크톱에서 467px, 391px 뷰포트에서 326px 너비를 썼다. 두 화면에서 ‘컴포넌트’가 한 줄로 표시됐고 좁은 화면의 문서 너비는 391px이었다.
- 날짜·시간 피커 9종에서 값 영역의 배경이 투명하고 오른쪽 버튼이 36×36px인 것을 확인했다. 연도 범위의 `2030` 왼쪽에 보이던 그림자는 제거됐다.
- 날짜 피커의 연·월 제목을 누르면 연도 목록을 먼저 연다. 연도를 고르면 월 목록, 월을 고르면 일 달력으로 이동한다. 피커 내부의 연도 목록에서 별도의 팝업 진입 효과를 제거하고, 세 화면이 같은 높이의 영역을 번갈아 쓰도록 했다.
- 브라우저에서 날짜·날짜 범위·날짜 시간·날짜 시간 범위 피커의 높이는 287px, 월·월 범위 피커의 높이는 255px이었다. 16개 전환에서 416개 표본을 확인했고 각 표본에서 목록이 하나씩 표시됐다. 391px 화면에서도 날짜 범위 피커의 연도 목록을 닫았다가 다시 열거나 현재 연도를 선택했을 때 높이가 유지됐다. 키보드로 연도·월·일 셀에 이어서 포커스가 이동했고 `2027-09-16`부터 `2027-09-19`까지 선택한 값이 입력 영역에 들어갔다.

### 피커 아이콘과 범위 값 표시

- 날짜·월·연도·시간 피커 9종의 기본 예제에서 36×36px 버튼과 18×18px 아이콘을 확인했다. 한 줄 피커는 위·오른쪽·아래 간격이 약 5.7px로 같았고, 두 줄 일시 피커는 버튼을 첫 줄에 맞췄다.
- 날짜·월·연도 범위의 빈 값에 시작과 종료 안내가 표시됐다. 날짜 범위는 첫 날짜 선택 후에도 확정 전 상태를 표시했고 두 번째 날짜를 고르면 확정된 두 값이 나타났다. 391px 화면에서 날짜 범위 구분선과 두 날짜가 한 줄에 들어갔다. 표기 예제는 `2026. 08. 22.`와 `22 Aug 2026` 사이를 전환하며 같은 날짜를 유지했다. 달력으로 날짜를 다시 고르면 현재 표기 형식으로 갱신됐다.

### 파일 업로드 선택과 교체

- 이전 상태 카드에서 파일명과 파일 크기가 같은 줄의 공간을 차지해 파일명이 잘게 나뉘었다. 공통 파일 행에서 이름과 크기를 위아래로 배치했다. 1910px와 391px 뷰포트에서 상태 카드 네 개의 파일명이 각 한 줄이었고, 길어서 줄인 파일명은 제목과 버튼의 접근성 이름에 전체 문자열이 남았다.
- 기본 예제는 하나의 파일 행으로 선택과 교체를 제공한다. 키보드로 첫 파일을 선택하고, 파일명 부분을 클릭해 더 긴 이름의 두 번째 파일로 교체했다. 두 경우 모두 파일을 고른 뒤 브라우저 읽기 완료 메시지가 나타났다. 별도 예제에서 진행 중 취소와 실패 후 재시도 완료도 확인했다.

### 파일 선택 초기 상태와 선택 그룹

- `UIFileInput` 기본 예제는 ‘파일 선택’ 버튼으로 시작한다. 파일을 선택하고 목록에서 제거하면 초기 상태로 돌아갔다.
- `UIFileUpload`는 파일이 들어오기 전에도 같은 선택 영역을 표시한다. 키보드로 파일을 고르고 마우스로 긴 파일명의 파일로 교체했다. 두 파일 모두 읽기 완료가 표시됐다. 수동 전송 예제에서는 취소와 실패 후 재시도를 확인했다.
- `UIToggleGroup`은 공통 바탕 위에 버튼을 배치하고 채움으로 선택 상태를 표시한다. 기본·호버·누름·키보드 포커스 카드가 각각 표시됐으며 방향키 이동과 Space 선택을 확인했다.
- `UICheckboxGroup`은 항목마다 공통 체크박스 표시를 사용한다. 키보드와 마우스로 메일과 앱을 선택해 제출했을 때 두 값이 표시됐다.
- 네 페이지는 391px 화면에서 문서 너비도 391px이었다.

### 파일 입력 높이와 전송 예제 후속 점검

- 기본 `UIInput`, 단일 파일 `UIFileInput`, `UIFileUpload`의 높이는 48px이었다. 긴 파일명을 선택하거나 교체하고, 첨부를 제거한 뒤에도 입력 높이가 같았다. 업로드 기본 예제는 파일명과 크기를 표시한다.
- 대기열 예제에서 세 파일이 처음부터 보였고, 한 파일씩 전송 중 상태를 거쳐 완료됐다. 초기화하면 세 파일이 모두 대기로 돌아갔다. 취소와 재시도 예제는 시작·진행·취소·실패·완료 상태에서도 입력 행 높이가 48px이었다.
- 391px 화면에서 긴 파일명은 한 줄에서 줄임표로 표시됐고, 대기열은 대기·전송 중·완료 상태에서 가로로 넘치지 않았다.

### 통합 파일 드롭존

- 파일 선택, 드롭, 붙여넣기 예제에서 카드 전체가 하나의 버튼으로 표시된다. 클릭과 Enter·Space로 파일 선택기를 열었다. 두 파일을 선택하고 모두 지우면 포커스가 카드로 돌아왔다.
- 브라우저 테스트 이벤트로 파일을 가져올 때의 강조, 드롭 후 목록과 강조 해제, 이미지 붙여넣기 후 썸네일, 용량 초과 거절을 확인했다. 391px 화면에서 가로 넘침이 없었다.

### 입력과 계층 탐색 후속 점검

- Editable 기본 예제는 값 자체를 눌러 편집한다. Enter로 확정하고 Escape로 취소한 뒤에도 입력 영역이 256×48px였다.
- Rating을 2점으로 바꾸면 처음 두 아이콘만 채워지고 각 항목의 배경은 투명했다. 아이콘마다 fill과 scale 전환을 사용한다. Stepper의 이전·다음 컨트롤로 배송에서 결제 단계로 이동했다.
- 범위 슬라이더를 양 끝으로 보내면 값은 50과 500이고 14×30px 손잡이는 48px 트랙 높이 안에 있었다. SpinButton의 증감 아이콘은 같은 크기였고 누르면 값이 4에서 5로 변경됐다. QuantityField는 입력 내부 outline 없이 외곽의 둥근 포커스 링을 사용했다.
- ColorPicker의 RGB 입력 세 개는 한 줄에 표시됐다. 키보드로 색조를 바꾸고 HSV 표시로 전환했다.
- TreeSelect는 클릭과 방향키로 목록을 열고 Escape와 하위 항목 선택으로 닫혔다. TreeView의 펼침 버튼을 눌러 가지를 접었다. CheckboxTree에서 이메일만 선택하면 상위의 공통 체크 표시가 혼합 상태로 바뀌었다. CascadeList에서 일본을 누르고 도쿄를 고르면 경로가 ‘아시아 / 일본 / 도쿄’로 갱신됐다.
- 수정한 입력·계층 탐색·오버레이 문서 14개는 391px 화면에서 문서 너비도 391px이었다.

### 오버레이와 탐색 메뉴 후속 점검

- stamp.is-web에서 기준으로 삼은 것은 하나의 팝오버 안에서 메뉴 내용을 바꾸는 구조와 Toast가 닫힌 상태에서 퇴장 효과를 재생하는 방식이다.
- NavigationMenu에서 두 하위 분류를 오갈 때 열린 팝오버는 하나였고 패널 ID가 유지됐다. Escape 후 포커스가 트리거로 돌아왔다. Toast는 표시 시 ui-toast-enter, 닫기 시 ui-toast-exit을 재생한 뒤 DOM에서 제거됐다.
- Dialog, Drawer, DatePicker에서 Escape로 닫고 재열었을 때 콘텐츠가 표시됐고 inert 상태가 아니었다. AlertDialog, Popover, Select, Combobox, MenuButton은 열고 Escape로 닫았으며 Tooltip은 키보드 포커스로 열고 Escape로 닫았다.
